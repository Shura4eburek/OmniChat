# omnivoice — инструмент обучения голосов для OmniChat: дизайн

Дата: 2026-10-04
Статус: согласовано в брейнсторминге, ждёт ревью спеки

## Цель

Дать игрокам и владельцам серверов один инструмент, который из любых исходников делает папку голоса, готовую для мода OmniChat: модель гарантированно грузится в sherpa-onnx (с полными метаданными — в отличие от «сырого» piper-экспорта, из-за которого модель `glados` роняла игру), рядом лежат `tokens.txt`, `espeak-ng-data`, `voice.json` и (необязательно) `portrait.png`.

Пользователи: автор мода и другие люди («у чувака уже есть датасет»), значит инструмент должен быть понятен без знания ML.

Критерии успеха:
- из сырых реплик персонажа (игра, видео) получается рабочий голос без ручной возни с форматами;
- готовый датасет (wav + текст) можно сразу обучить;
- чужую готовую piper/onnx-модель можно упаковать для мода;
- каждый выпущенный голос проходит `verify` — синтез через sherpa-onnx без падения;
- без видеокарты NVIDIA обучение возможно через Google Colab.

## Три входа в один конвейер

```
сырое аудио ──(B: slice, transcribe, review)──▶ датасет ──(A: check, train, export)──▶ модель ──(C: pack, verify, install)──▶ папка мода
```

- B — сырое аудио/видео.
- A — готовый датасет (`import`).
- C — только упаковка готовой модели.

## Структура

Пакет `tools/omnivoice/` в репозитории мода (Python 3.11, `uv`), команда `omnivoice`.

Группы зависимостей:
- базовая: `onnx`, `sherpa-onnx`, `pillow`, `typer`, `tomli-w` — для `init`, `import`, `check` (без фонемизации, см. ниже), `pack`, `verify`, `install`;
- `[prep]`: `faster-whisper`, `silero-vad`, `demucs`, `pyloudnorm`, `num2words`, `soundfile` — для `slice` и `transcribe`;
- `[phonemize]`: `piper-phonemize` — фонемизация для `check` и `export` (`tokens.txt`, `espeak-ng-data`);
- `[ui]`: `gradio`.
Обучение и `export` (ему нужны torch и piper-train) идут только в Docker-образе или Colab; torch/piper-train в локальное окружение не ставятся. Локальный `omnivoice export` запускает экспорт в том же образе.

### Проект голоса

Одна папка на голос:
```
<project>/
  project.toml      # name, language (ru), espeak_voice (ru), base_checkpoint, sample_rate=22050,
                    # display: name/description/gender/sample/license, steps: состояние этапов
  raw/              # исходники (B)
  segments/         # фразы, WAV 22050 Гц моно 16 бит
  metadata.csv      # LJSpeech: id|text  (+ review.json: confidence, флаги «проверить»/«выкинуть»)
  train/            # чекпойнты, логи, previews/<step>/*.wav
  export/<voice>/   # готовая папка мода
```
Все команды идемпотентны: повторный запуск не ломает сделанное; `project.toml` хранит пройденные этапы.

## Команды

| Команда | Вход | Что делает |
|---|---|---|
| `init <dir>` | — | создаёт проект; язык, espeak voice и базовый чекпойнт по умолчанию из языка (ru → `irina` medium) |
| `slice` | `raw/*` | ffmpeg-декод любого аудио/видео; `--isolate` — отделение голоса demucs; silero-vad режет на фразы 1–15 с (короткие склеивает, длинные дорезает); 22050 Гц моно; нормализация громкости; 150 мс тишины по краям |
| `transcribe` | `segments/` | faster-whisper (GPU: large-v3, CPU: medium), язык проекта; нормализация текста (числа словами `num2words`, удаление непроизносимых символов); фразы с низкой уверенностью получают флаг «проверить» |
| `import <dir>` | wav + `metadata.csv`/LJSpeech или пары `.wav`+`.txt` | копирует/ресемплирует в `segments/`, пишет `metadata.csv` |
| `check` | датасет | отчёт: суммарная длительность (предупреждение < 10 мин, рекомендация ≥ 30 мин), фразы вне 1–15 с, клиппинг > 0,1 % сэмплов, пустой текст, строки, которые фонемизатор не обработал; выкинутые фразы не учитываются |
| `train` | датасет | `--docker` (по умолчанию, `docker run --gpus all`): дообучение piper medium с базового чекпойнта; размер батча под VRAM; чекпойнт каждые N эпох; resume; превью 3 фраз на каждом чекпойнте. `--colab`: собирает `dataset.zip` + инструкцию для ноутбука. `--build`: собирает образ локально |
| `export [--ckpt]` | чекпойнт | piper-экспорт в ONNX; всегда дописывает метаданные `model_type=vits`, `comment=piper`, `language`, `voice`, `has_espeak=1`, `n_speakers=1`, `sample_rate`, `omnivoice_version`; строит `tokens.txt` из `phoneme_id_map`; копирует `espeak-ng-data` |
| `pack [--onnx X]` | экспорт или чужая модель | собирает `export/<voice>/`: модель, `tokens.txt`, `espeak-ng-data`, `voice.json`, `portrait.png` (загруженная картинка → 32×32 nearest, ≤ 8 КБ); недостающие метаданные чужой модели дописывает (язык — из её `.onnx.json` `espeak.voice` или `--voice`); проверяет теми же правилами, что мод |
| `verify` | папка мода | в отдельном процессе грузит модель через sherpa-onnx и синтезирует тестовую фразу на языке модели; сохраняет `sample.wav`; падение процесса → понятная ошибка, а не краш |
| `install <dir>` | папка мода | копирует в `config/omnichat/models/<voice>` клиента или сервера (путь указывается или ищется в типичных местах) |
| `ui` | — | веб-интерфейс (см. ниже) |

### Правила «как в моде»
`pack` и `verify` используют те же лимиты, что `VoiceMetaReader`/`OnnxMetadata` мода: `name` ≤ 32, `description` ≤ 200, `sample` ≤ 120, `language` ≤ 8; портрет PNG 16×16 или 32×32 ≤ 8192 байт; обязательны `n_speakers`, для piper — `voice`. Константы живут в одном модуле `omnivoice/modrules.py` с комментарием-ссылкой на Java-источники.

## Обучение

- Docker-образ `omnivoice-train` (`tools/omnivoice/docker/Dockerfile`): CUDA + piper training (PyTorch Lightning) + `piper-phonemize`; проект монтируется в `/work`.
- Дообучение базового piper medium (22050 Гц) из `rhasspy/piper-checkpoints` (ru: denis/dmitri/irina/ruslan; en: lessac); базовый чекпойнт скачивается один раз в кэш.
- Colab: `tools/omnivoice/notebooks/omnivoice_colab.ipynb` — ставит omnivoice из GitHub, принимает `dataset.zip`, обучает на GPU Colab, делает `export` + `pack` + `verify`, отдаёт `voice.zip`.

## Веб-интерфейс (`omnivoice ui`)

Gradio с собственной темой и CSS в бирюзовом HUD-стиле мода (акцент `#35E0C8`, фон `#0B0A0E`, тонкие рамки с уголками, моноширинный шрифт). Утверждённый макет: `.superpowers/brainstorm/*/content/omnivoice-layout.html`, вариант B + полоса шагов.

- Шапка: `OMNIVOICE`, состояние окружения (GPU, Docker ✓/✗, Colab-режим).
- Слева: список проектов (+ «новый проект»), под ним разделы текущего проекта: Аудио, Нарезка, Фразы (со счётчиком флагов), Проверка, Обучение, Упаковка.
- Сверху над содержимым: полоса шагов 1–6 с отметками «готово ✓ / текущий / не начат»; клик по шагу — переход в раздел.
- Фразы: таблица (▶ прослушать, id, редактируемый текст, мини-волна, длительность), фильтр «только ⚑», кнопки «выкинуть»/«вернуть», статистика (фраз, минут речи, к проверке).
- Обучение: кнопка старт/стоп/продолжить, эпоха X/Y, график loss, прослушивание превью по чекпойнтам, «экспортировать этот чекпойнт».
- Упаковка: поля voice.json, загрузка портрета с предпросмотром 32×32, «Упаковать», результат `verify` с плеером `sample.wav`, «Установить в Minecraft».
- Длинные операции (slice, transcribe, train) идут в фоне; разделы доступны во время обучения.

## Ошибки

- нет Docker / нет NVIDIA GPU → сообщение «используй Colab» со ссылкой на ноутбук;
- нехватка VRAM → автоматическое уменьшение батча и повтор;
- мало данных → предупреждение в `check` (обучение не блокируется);
- `verify` упал → причина (код выхода процесса, последние строки лога sherpa) и подсказка;
- нет ffmpeg → подсказка установки.

## Права на голоса

README инструмента: голоса из игр и чужих записей защищены правами; публиковать только с разрешения. `voice.json` получает необязательное поле `license` (мод его игнорирует).

## Тестирование

pytest без GPU:
- запись метаданных ONNX, построение `tokens.txt`, сборка `voice.json`, правила «как в моде» (лимиты, портрет);
- нарезка: склейка коротких и дорезка длинных фраз на синтетических сигналах;
- нормализация текста (числа, символы);
- `pack` + `verify` сквозняком на копии модели `denis`, если она есть локально (иначе skip);
- `import` LJSpeech и пар wav/txt.
Ручные проверки: обучение 2 шага в Docker, прогон Colab-ноутбука, установка результата и озвучка в игре.
