# omnivoice

Инструмент превращает сырое аудио или готовый датасет в обученный голос Piper — или упаковывает уже готовую модель — в папку формата OmniChat (sherpa-onnx). Результат кладётся в `config/omnichat/models/` мода.

> **Права.** Голоса из игр, фильмов и чужие записи защищены авторским правом и правами на голос. Обучайте и публикуйте голос только с разрешения владельца записей. В `voice.json` есть необязательное поле `license` (мод его игнорирует) — указывайте в нём условия использования. Ответственность за использование чужого голоса лежит на вас.

## Три точки входа

```
A. Сырое аудио ──► init ► slice ► transcribe ► (правка фраз) ► check ► train ► export ─┐
B. Готовый датасет ► init ► import ► check ► train ► export ───────────────────────────┼► pack ► verify ► install
C. Готовая модель (.onnx + .onnx.json) ────────────────────────────────────────────────┘
```

Все то же самое доступно в веб-интерфейсе: `omnivoice ui`.

## Требования

- Windows 10 версии 22H2 или Windows 11, 64 бит.
- Видеокарта NVIDIA и свежий драйвер NVIDIA для Windows — для обучения. Без неё обучайте в Google Colab (см. ниже).
- Около 15 ГБ свободного места на диске `C:` (подробности ниже) и интернет для первой установки.
- Для пути C (упаковать готовую модель) хватает самого omnivoice: без GPU, WSL и ffmpeg.

## Установка

1. Скачайте репозиторий: `git clone` или кнопка **Code → Download ZIP** на GitHub, затем распакуйте архив.
2. Откройте папку `tools/omnivoice` и дважды щёлкните **`install-omnivoice.bat`**. Установщик сам поставит [uv](https://docs.astral.sh/uv/) (менеджер Python), Python-пакеты, создаст папку проектов `%USERPROFILE%\omnivoice-projects`, ярлык **OmniVoice** на рабочем столе и откроет веб-интерфейс.
3. В интерфейсе откройте раздел **«Установка»** и нажмите **«Установить зависимости»**. Дальше всё идёт само, прогресс и журнал видны там же. Повторное нажатие докачивает только то, чего не хватает.

Без видеокарты NVIDIA (на компьютере нет `nvidia-smi`) среда обучения WSL не ставится: «Установить зависимости» ставит только пакеты и ffmpeg, а WSL и среда обучения в списке помечены «необязательно» — обучайте в Colab (`omnivoice train --colab`).

### Что ставится и сколько места занимает

Цифры сняты на реальной установке (RTX 4070 Ti, Windows 11, быстрый интернет — около 8 минут).

| Что | Скачивается | На диске | Где лежит |
|---|---|---|---|
| Python-пакеты omnivoice (нарезка, распознавание, интерфейс) | — | ставит `install-omnivoice.bat` | `tools/omnivoice/.venv` |
| ffmpeg 9.0 (для работы с аудио) | ~100 МБ | 200 МБ | `%LOCALAPPDATA%\omnivoice\ffmpeg` |
| Образ Ubuntu 24.04 для WSL | 390 МБ | удаляется после настройки среды (при пересоздании среды скачивается снова) | `%LOCALAPPDATA%\omnivoice\wsl` |
| Среда обучения: PyTorch 2.14 + CUDA 12.6, piper1-gpl 1.8.0 | ~3 ГБ | ~9 ГБ внутри, файл диска WSL — около 13 ГБ | `%LOCALAPPDATA%\omnivoice\wsl\omnivoice\ext4.vhdx` |
| Модель оценки качества UTMOS (при первом обучении) | 390 МБ | 390 МБ | внутри среды WSL |
| Базовый чекпойнт Piper (при первом обучении, на каждый базовый голос) | 850 МБ | 1,7 ГБ (оригинал + очищенная копия) | `%LOCALAPPDATA%\omnivoice\checkpoints` |
| Необязательно: XTTS v2 для синтетики (галочка на «Установке») | ~4,5 ГБ | ~8,3 ГБ внутри среды (окружение 6,5 ГБ + модель 1,8 ГБ) | `/opt/omnivoice/xtts` в среде WSL |

Файл диска WSL (`ext4.vhdx`) растёт, но сам не уменьшается: временные файлы установки остаются в его размере. Поэтому закладывайте около 15 ГБ под установку и ещё ~2 ГБ на каждый базовый голос.

**Что такое WSL.** WSL (Windows Subsystem for Linux) — встроенный в Windows компонент от Microsoft, который запускает настоящий Linux рядом с Windows. Обучение Piper работает только под Linux, поэтому omnivoice создаёт себе отдельный дистрибутив WSL с именем **`omnivoice`** из официального образа Ubuntu и ставит туда PyTorch и piper. Видеокарта пробрасывается в WSL драйвером NVIDIA для Windows — отдельный драйвер в Linux не нужен. Другие ваши дистрибутивы WSL omnivoice не трогает. Удалить среду целиком: `wsl --unregister omnivoice` и папка `%LOCALAPPDATA%\omnivoice\wsl`.

Если WSL на компьютере ещё нет, omnivoice включит его сам: Windows покажет запрос администратора (UAC) — подтвердите его. После этого нужна **перезагрузка**; после неё откройте OmniVoice ярлыком на рабочем столе и снова нажмите «Установить зависимости» — установка продолжится с того же места. Если и после перезагрузки WSL не запускается, omnivoice не просит перезагрузиться ещё раз, а подсказывает включить виртуализацию в BIOS/UEFI и компонент «Платформа виртуальной машины».

### Где хранятся зависимости

По умолчанию всё тяжёлое (диск среды WSL, базовые чекпойнты, ffmpeg) лежит в `%LOCALAPPDATA%\omnivoice` на диске C: — пути в таблице выше даны для этого случая. Папку можно сменить, например на `G:\omnivoice`; уже установленное переносится туда целиком. Проекты голосов это не затрагивает.

- **В интерфейсе:** раздел «Установка» → поле «Папка для зависимостей» → впишите новую папку → «Сменить / перенести». Под полем видно, сколько места свободно на том диске; ход переноса — в журнале ниже.
- **Из командной строки:**

```bash
uv run omnivoice data-dir                      # где лежит сейчас, откуда взята настройка, сколько занято
uv run omnivoice data-dir "G:\omnivoice"       # перенести туда
uv run omnivoice setup --data-dir "G:\omnivoice"   # на новом компьютере: сразу ставить туда
```

Новая папка должна быть на локальном диске NTFS (не сетевом и не флешке), и на нём нужно свободное место: текущий объём + 10 %. Сначала переносится среда WSL (`wsl --manage omnivoice --move`), затем копируется остальное, и только после проверки копии omnivoice переключается на новую папку и удаляет старые файлы — если что-то пошло не так, всё продолжает работать со старого места. Если пишет, что диск среды занят, — закройте Docker Desktop или выполните `wsl --shutdown` и повторите. Настройка хранится в `%APPDATA%\omnivoice\config.json`; переменная окружения `OMNIVOICE_CACHE`, если задана, важнее неё.

### Если у вас уже есть Docker

Docker Desktop больше не нужен. Если он у вас уже стоит и видит GPU, omnivoice использует его как запасной вариант, когда среда WSL не готова: образ собирается командой `omnivoice train --build` и весит около 10 ГБ. Когда среда WSL готова, обучение идёт в ней.

### Из командной строки

```bash
cd tools/omnivoice
uv sync --all-extras --inexact     # Python-пакеты (то же делает install-omnivoice.bat)
uv run omnivoice setup --check     # только показать, чего не хватает
uv run omnivoice setup             # поставить ffmpeg, WSL и среду обучения (то же, что кнопка в интерфейсе)
```

Коды выхода `omnivoice setup`: `0` — всё готово (необязательные пункты не считаются), `1` — чего-то не хватает или установка прервалась с ошибкой, `2` — нужна перезагрузка Windows (после неё запустите `omnivoice setup` ещё раз). `setup --check` возвращает `0` или `1`.

- `uv sync` без extras — только база: упаковка, проверка, установка (включая sherpa-onnx-core). Хватает для пути C.
- `--all-extras` = `--extra prep --extra ui`: `prep` — нарезка и распознавание (faster-whisper, silero-vad, demucs, pyloudnorm), `ui` — веб-интерфейс (gradio, tensorboard).

Важно: `uv sync --extra X` без `--inexact` ставит **только** перечисленные extras и удаляет остальные. Поэтому не запускайте `uv sync --extra prep`, а потом `uv sync --extra ui` — второй вызов снесёт `prep`. Перечисляйте всё нужное в одной команде.

torch и piper-train в Windows не ставятся: обучение идёт в среде WSL `omnivoice` (или в Docker, или в Colab).

## Быстрый старт

### C. Упаковать готовую модель (без GPU)

```bash
uv run omnivoice pack --onnx model.onnx --config model.onnx.json \
    --name "Мой голос" --language Russian --portrait portrait.png --out ./voices
uv run omnivoice verify ./voices/<папка>
uv run omnivoice install ./voices/<папка>
```

Опции `pack --onnx`: `--config` (.onnx.json), `--voice` (голос espeak, например `ru`; по умолчанию берётся из конфига), `--name` (обязательно), `--language` (английское название языка; по умолчанию выводится из `--voice` или из конфига: `ru` → `Russian`, `en-us` → `English`, иначе `Russian`), `--out` (куда собрать, по умолчанию текущая папка), `--portrait` (любая картинка, будет приведена к PNG для мода).

`install` без `--target` ищет папку `models` сам (`%APPDATA%\.minecraft`, Prism Launcher, `run/config/omnichat/models` рядом); если не нашёл — укажите `--target`. `--overwrite` заменяет уже установленный голос.

### A. Из сырого аудио

```bash
uv sync --all-extras
uv run omnivoice init ./my-voice --name "Мой голос" --language ru   # ru или en; --base denis|dmitri|irina|ruslan|lessac
# положите записи в ./my-voice/raw/
uv run omnivoice slice -p ./my-voice            # --isolate убирает музыку (demucs)
uv run omnivoice transcribe -p ./my-voice       # --model для выбора модели Whisper
uv run omnivoice check -p ./my-voice
uv run omnivoice train -p ./my-voice            # GPU, в среде WSL omnivoice
uv run omnivoice export -p ./my-voice           # ONNX + упаковка + проверка
uv run omnivoice install ./my-voice/export/<папка>
```

`export` сам упаковывает голос (как `pack`) и проверяет его (как `verify`) — отдельно запускать `pack` и `verify` не нужно. `pack -p ./my-voice --portrait portrait.png` нужен только чтобы пересобрать уже экспортированную модель, например добавить или сменить портрет.

Имя папки голоса берётся из имени голоса с транслитерацией: «Мой голос» → `moy_golos`.

Фразы после `transcribe` удобно проверять и править в веб-интерфейсе.

### B. Из готового датасета

```bash
uv run omnivoice init ./my-voice --name "Мой голос" --language ru
uv run omnivoice import ./dataset -p ./my-voice   # LJSpeech или пары .wav + .txt
uv run omnivoice check -p ./my-voice
uv run omnivoice train -p ./my-voice
uv run omnivoice export -p ./my-voice             # ONNX + упаковка + проверка
uv run omnivoice install ./my-voice/export/<папка>
```

Тексты при импорте нормализуются так же, как после `transcribe` (числа словами, ремарки `*смеётся*` и эмодзи убираются); такие фразы получают флаг для проверки.

### Обучение

`omnivoice train` дообучает голос поверх базового чекпойнта Piper. `--epochs` означает дополнительные эпохи сверх базового чекпойнта (по умолчанию 1000). Обучение продолжается с последнего чекпойнта; `--no-resume` начинает заново. Обучение идёт в среде WSL `omnivoice` (её ставит «Установить зависимости»), а если она не готова — в Docker, если он есть; `omnivoice train --build` только собирает Docker-образ. При первом обучении скачивается базовый чекпойнт и модель оценки качества UTMOS (390 МБ), поэтому первая эпоха идёт на несколько минут дольше. Если чекпойнт с нужной эпохой уже есть, `train` пишет «Цель уже достигнута» и ничего не запускает — увеличьте `--epochs`. Промежуточное качество: `omnivoice previews -p ./my-voice` показывает чекпойнты и достаёт аудио-превью из логов обучения; `omnivoice export --ckpt <файл>` экспортирует выбранный чекпойнт (по умолчанию последний).

### Синтетика (XTTS v2)

Если записей персонажа мало (минута-две), Piper быстро выучивает их наизусть и плохо говорит новые фразы. Страница «Синтетика» (шаг 5, необязательный) озвучивает много новых фраз голосом персонажа моделью XTTS v2 — она копирует голос по нескольким секундам образца — и добавляет их к обучению.

1. **Установка.** На «Установке» поставьте галочку «и XTTS v2 для синтетики» и нажмите «Установить зависимости». XTTS ставится в ту же среду WSL отдельным окружением (`/opt/omnivoice/xtts`, ≈ 8 ГБ вместе с моделью) и нужна только для этой страницы; нужна видеокарта NVIDIA.
2. **Образцы голоса.** 3–5 оригинальных фраз длиной 3–12 с без меток подбираются сами; лишнюю уберите ✕, «Подобрать автоматически» вернёт подбор.
3. **Что озвучить.** Сколько минут синтетики (по умолчанию 15) и свои фразы в стиле персонажа — по одной на строку, они озвучиваются первыми. Остальное добирается из встроенного корпуса русских предложений так, чтобы покрыть как можно больше разных сочетаний звуков.
4. **Сгенерировать.** Прогресс и оставшееся время видны над журналом. «Стоп» дописывает текущую фразу и останавливается; «Догенерировать» доделывает только недостающее и не удавшееся.
5. **Проверка.** Каждую фразу распознаёт Whisper: совпало и темп нормальный — фраза принята; заметно не совпало, слишком быстро или медленно, длинная пауза, перегруз — «спорная»; совсем не то — «брак». Спорные ждут решения: ▶ послушать, ✓ принять, ✕ выкинуть; ↺ отменяет ваше решение. Без Whisper фразы не проверяются и в обучение не идут.

На «Обучении» видно, сколько синтетики пойдёт в обучение; её можно отключить галочкой. «Вес оригинала» (по умолчанию ×3) повторяет настоящие записи в датасете столько раз, чтобы живой голос перевешивал синтетический. Всё лежит в папке проекта: `synth/synth.json` (фразы и решения), `synth/lines.txt` (ваши фразы), `synth/wavs/` (22 050 Гц, моно).

**Лицензия.** XTTS v2 распространяется по Coqui Public Model License ([карточка модели](https://huggingface.co/coqui/XTTS-v2)) — только некоммерческое использование. Голоса, обученные с синтетикой XTTS, тоже используйте только некоммерчески. Без синтетики ограничение не действует. Корпус предложений взят из Mozilla Common Voice (CC0), подробности — `omnivoice/data/README.md`.

### Веб-интерфейс

```bash
uv sync --all-extras
uv run omnivoice ui --projects ./voices      # --port 7860, --no-browser
```

Интерфейс слушает только `127.0.0.1` и показывает проекты из папки `--projects`.

Не работайте с одним проектом одновременно из CLI и из веб-интерфейса: такой режим не поддерживается (интерфейс блокирует проект только от своих же параллельных действий).

## Colab (нет GPU)

```bash
uv run omnivoice train -p ./my-voice --colab
```

Команда собирает zip с датасетом и печатает ссылку на ноутбук (`colab.NOTEBOOK_URL`). Откройте ноутбук, загрузите zip и дождитесь обучения — ноутбук сам экспортирует, упакует и проверит голос и отдаст архив с папкой голоса. Дальше локально:

1. скачайте zip из Colab;
2. распакуйте его — получится папка голоса;
3. выполните `uv run omnivoice install <папка>`.

Запускать `export` или `pack` локально после Colab не нужно. Ноутбук доступен по ссылке после слияния ветки в `main`.

## Что внутри папки голоса

Это тот же формат, что описан в корневом README, раздел «Оформление голосов»:

```
<имя>/
  <имя>.onnx          модель с метаданными sherpa-onnx (n_speakers, voice)
  <имя>.onnx.json     конфиг Piper
  tokens.txt          таблица токенов
  espeak-ng-data/     данные espeak (нужен phontab)
  voice.json          необязательно: оформление
  portrait.png        необязательно: PNG 16x16 или 32x32, не больше 8 КБ
```

`voice.json`:

```json
{ "name": "Денис", "description": "Спокойный мужской голос", "language": "ru",
  "gender": "male", "sample": "Привет, я Денис." }
```

| Поле | Лимит | Назначение |
|---|---|---|
| `name` | 32 символа | Имя в меню |
| `description` | 200 | Описание в карточке |
| `language` | 8 | Код языка |
| `gender` | 16 | Свободное поле |
| `sample` | 120 | Фраза для прослушивания |
| `license` | — | Необязательно, мод игнорирует |

`omnivoice verify` проверяет эти лимиты и загружает модель в sherpa-onnx отдельным процессом.

## Если что-то не работает

- **WSL не установлен** — нажмите «Установить зависимости» (или `omnivoice setup`) и подтвердите запрос администратора (UAC). Отказались от запроса — нажмите ещё раз. После установки WSL перезагрузите компьютер, откройте OmniVoice ярлыком на рабочем столе и снова нажмите «Установить зависимости». Если пишет про виртуализацию или WSL не запускается и после перезагрузки — включите виртуализацию в BIOS/UEFI (Intel VT-x / AMD SVM) и компонент Windows «Платформа виртуальной машины», перезагрузитесь и нажмите кнопку ещё раз. Не получается автоматически — откройте PowerShell от администратора и выполните `wsl --install --no-distribution`.
- **WSL устарел** — то же: «Установить зависимости» обновит его (`wsl --update`).
- **Старый драйвер NVIDIA** — для GPU в WSL нужен драйвер NVIDIA для Windows версии 528 или новее (лучше последний); ставьте свежий с nvidia.com или через GeForce Experience / NVIDIA App. Драйвер внутри Linux ставить не нужно.
- **«Среда WSL готова, но не видит видеокарту NVIDIA»** — обновите драйвер NVIDIA для Windows и перезагрузите компьютер. Проверить: `wsl -d omnivoice -u root -- /usr/lib/wsl/lib/nvidia-smi` должен показать вашу видеокарту. Пока GPU не виден, обучайте в Colab.
- **Не хватает места на диске** — нужно около 15 ГБ на `C:` (см. таблицу выше). Освободите место и повторите «Установить зависимости» — готовые шаги не повторятся. Место занимают и проекты: папка `train/` проекта хранит чекпойнты (сотни МБ каждый); её можно удалить, если обучение закончено и голос экспортирован.
- **Настройка среды WSL оборвалась** (нет интернета, закрыли окно) — просто нажмите «Установить зависимости» ещё раз: продолжится с прерванного шага. Начать среду с нуля: `wsl --unregister omnivoice`, затем снова «Установить зависимости».
- **Нет GPU / Docker не запускается** — используйте Colab (`train --colab`) или путь C.
- **`verify` не прошёл** — прочитайте сообщение: чаще всего нет `n_speakers` или `voice` в метаданных `.onnx`, нет `tokens.txt` / `espeak-ng-data`, либо превышены лимиты `voice.json`/портрета. Пересоберите папку через `pack`.
- **Мало видеопамяти (VRAM)** — при ошибке `CUDA out of memory` `train` сам вдвое уменьшает батч (до минимума 4), пишет «Не хватило видеопамяти — уменьшаю батч до N и продолжаю» и продолжает с последнего чекпойнта. Если не хватает даже при батче 4 — закройте другие приложения с GPU или обучайте в Colab.
- **Проверка произносимости пропущена** (`check` пишет «Фонемизатор не установлен») — фонемизатор Piper не входит в зависимости; запустите проверку с ним: `uv run --with piper-tts omnivoice check -p ./my-voice`.
- **«Файл … повреждён»** — `project.toml`, `metadata.csv` или `review.json` испорчены (например, правкой вручную). Почините файл или восстановите из копии.
- **`ffmpeg не найден`** — нажмите «Установить зависимости» (omnivoice поставит свой ffmpeg) или `winget install ffmpeg` и перезапустите терминал.
- **`install` не нашёл папку models** — укажите `--target <путь>\config\omnichat\models`, затем в игре `/omnichat reload`.
